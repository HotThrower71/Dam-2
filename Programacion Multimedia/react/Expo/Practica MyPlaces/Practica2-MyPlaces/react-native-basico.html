0 · Mapa mental y primeros ficheros empieza aquí

Si entiendes estas cuatro ideas, todo lo demás son detalles.

1 · La pantalla es una función de los datos

Tú no dices “pon un texto aquí y cámbialo después”. Dices “con estos datos, la pantalla es así”. Si los datos cambian, React vuelve a ejecutar tu función y actualiza lo necesario.

2 · Todo es un componente

Una pantalla, un botón, una tarjeta: son funciones que devuelven lo que se ve. Se combinan como piezas de Lego.

3 · Los datos bajan, los eventos suben

El padre pasa datos al hijo con props. El hijo avisa al padre de que algo pasó llamando a una función que el padre le dio.

4 · El estado es la memoria

Lo que cambia con el tiempo (texto escrito, lista, “cargando”) vive en estado (useState). Cambiar el estado = repintar.
Datos (estado + props)→Tu componente (función)→JSX (descripción)→Pantalla
Usuario pulsa→onPress→setEstado(nuevo)→React vuelve a ejecutar el componente

Los dos primeros ficheros que verás: _layout.jsx e index.jsx

En un proyecto con Expo Router, todo está dentro de la carpeta src/app/, y los dos primeros ficheros son estos. Una analogía: una tele.

📺 _layout.jsx = el marco de la tele

El aparato: la pantalla con su borde y botones. No cambia nunca. Su trabajo es <Stack />: “aquí dentro se muestra la pantalla que toque, con su barra de arriba”. Se ejecuta una vez y se queda.

🎬 index.jsx = un canal

Lo que sale cuando enciendes la tele: la primera pantalla, la ruta /. Luego habrá más canales (nuevo.jsx, descubre.jsx) y cambiarás entre ellos, pero el marco es siempre el mismo.

El nombre del fichero ES la ruta. index.jsx = /, nuevo.jsx = /nuevo. Si lo llamas indice.jsx, la ruta sería /indice y la pantalla de inicio no existiría (error “Unmatched Route”). Los nombres de src/app se escriben tal cual, en inglés.
Regla corta: ¿cambia de una pantalla a otra (textos, listas, botones)? → va en la pantalla. ¿Rodea a todas (barra, navegación)? → va en el layout. Un componente solo se ve donde lo escribes como etiqueta; el layout no es un “registro” de componentes.

¿Qué es un Stack? La pila de pantallas

Stack significa “pila”. Piensa en folios apilados en una mesa: solo ves el de arriba.

  • push = poner un folio encima (abres una pantalla nueva).
  • back = quitar el de arriba y ver el de debajo (volver atrás).
  • <Stack /> es el componente de Expo Router que gestiona esa pila: sabe qué pantallas hay apiladas, dibuja la de arriba y pone la barra superior con la flecha ‹.
push('/nuevo')       push('/detall/3')       back()
┌──────────┐         ┌──────────┐            ┌──────────┐
│          │         │ detall/3 │ ← ves      │          │
│ nuevo    │ ← ves   │ nuevo    │            │ nuevo    │ ← ves
│ index    │         │ index    │            │ index    │
└──────────┘         └──────────┘            └──────────┘

El mismo ejemplo, línea a línea

// Estás en index. La pila es: [index]
router.push('/nuevo');      // pila: [index, nuevo]              → ves «nuevo»
router.push('/detall/3');   // pila: [index, nuevo, detall/3]    → ves «detall/3»
router.back();              // pila: [index, nuevo]              → ves «nuevo»
router.back();              // pila: [index]                     → ves «index»
router.replace('/nuevo');   // cambia la de arriba por «nuevo»   → no se puede volver a la anterior

Qué te da <Stack />

CosaExplicación
Barra superiorCon el título (por defecto, el nombre del fichero) y la flecha ‹ cuando hay pantallas debajo.
Botón atrásLa flecha de la barra, el botón atrás de Android y el gesto de deslizar en iOS llaman a back solos.
AnimaciónLa pantalla nueva entra deslizándose y sale al volver.
Las de debajo siguen vivasindex no se destruye al abrir nuevo: al volver conserva su estado. Por eso, para recargar datos al volver se usa useFocusEffect.

Stack no tiene contenido propio: solo es el sistema que apila y muestra tus pantallas. El contenido sale de los ficheros de src/app/.

Un fichero, un export default

En cada fichero puede haber muchas funciones, pero solo una con export default: la pieza “principal” del fichero. En src/app/ esa es la pantalla.

La estructura de un fichero, de arriba abajo

// 1. IMPORTS (arriba del todo)
import { StyleSheet, Text, View } from 'react-native';

// 2. Piezas auxiliares: SIN export default, solo se usan en este fichero
function Titulo() {
  return <Text style={estilos.titulo}>MyPlaces</Text>;
}

// 3. El componente principal: SOLO UNO con export default
export default function Inicio() {
  // 3a. aquí irían el estado y las funciones (useState, eventos…)
  return (
    <View>
      <Titulo />
      <Text>Tour</Text>
    </View>
  );
}

// 4. Estilos (opcional, al final)
const estilos = StyleSheet.create({ titulo: { fontSize: 24 } });
Si necesitas esa pieza auxiliar en varias pantallas, sácala a src/components/ en su propio fichero (con su export default) e impórtala donde la uses. Más en la sección 2.

2 · Ficheros, export e import cómo se conectan las piezas

Una app son muchos ficheros que se conectan: uno exporta una pieza y otro la importa para usarla. Aquí aprendes cómo.

Antes de seguir: si aún no tienes claro qué es _layout.jsx y qué es index.jsx, repasa el final de la sección 0.
Quiero…Lo pongo en…

Un componente de src/components se puede importar en el layout, en una pantalla o dentro de otro componente. No pertenece a un sitio concreto: pertenece a donde lo importes.
Ojo, confusión habitual: el layout no es un “registro” donde se exportan los componentes para que se vean. Un componente se ve solo donde lo escribes como etiqueta (<BannerRed />). Para eso: 1) lo exportas en su propio fichero, 2) lo importas en el fichero donde lo quieres ver y 3) lo pones en su return. Ese fichero puede ser una pantalla, otro componente o el layout (si lo pones en el layout, se ve en todas las pantallas). Las pantallas sí se registran solas, por existir como fichero en src/app/.

Importar: export por defecto y con nombre

// src/components/BannerRed.jsx
export default function BannerRed() { /* … */ }          // export POR DEFECTO

// src/storage/lugares.js
export async function leerLugares() { /* … */ }          // export CON NOMBRE
export async function guardarLugares(l) { /* … */ }

// En otro fichero:
import BannerRed from '../components/BannerRed';                     // por defecto: sin llaves
import { leerLugares, guardarLugares } from '../storage/lugares';    // con nombre: con llaves

Importar un componente en el layout

Los pasos son siempre los mismos: 1) el componente tiene su export, 2) lo importas arriba con la ruta correcta, 3) lo usas como etiqueta.

// src/app/_layout.jsx
import { Stack } from 'expo-router';
import { View } from 'react-native';
import BannerRed from '../components/BannerRed';   // ← importar un componente

export default function Layout() {
  return (
    <View style={{ flex: 1 }}>
      <BannerRed />            {/* se ve en TODAS las pantallas */}
      <Stack />                {/* aquí se dibuja la pantalla activa */}
    </View>
  );
}

3 · Componentes y props

Un componente es una función que devuelve JSX. Las props son sus parámetros.

Reglas de oro
  • El nombre empieza por mayúscula (Saludo, no saludo): así React sabe que es un componente y no una etiqueta nativa.
  • Recibe un solo parámetro: el objeto de props. Se suele desestructurar: ({ nombre, edad }).
  • Las props son de solo lectura: el hijo no las modifica; si hay que cambiarlas, avisa al padre.
  • Devuelve un único elemento raíz (o un fragmento <>…</>).
function Saludo({ nombre, edad }) {
  return (
    <View>
      <Text>Hola {nombre}</Text>
      <Text>Tienes {edad} años</Text>
    </View>
  );
}

// Usarlo varias veces con datos distintos
<Saludo nombre="Ana" edad={20} />
<Saludo nombre="Luis" edad={31} />

Props especial: children

Lo que escribes entre las etiquetas de un componente llega como children. Sirve para crear contenedores reutilizables.

function Caja({ titulo, children }) {
  return (
    <View style={{ borderWidth: 1, padding: 8 }}>
      <Text style={{ fontWeight: 'bold' }}>{titulo}</Text>
      {children}
    </View>
  );
}

<Caja titulo="Mi lugar">
  <Text>Descripción</Text>
  <Text>Dirección</Text>
</Caja>

Props que son funciones (cómo el hijo avisa al padre)

El hijo no puede cambiar datos del padre. Pero el padre puede darle una función: <Tarjeta onBorrar={() => borrar(id)} />. Dentro, el hijo hace <Pressable onPress={onBorrar}>. Así el hijo no sabe cómo se borra, solo avisa. Ese es el patrón de TarjetaLugar de la práctica.

6 · Estilos: StyleSheet y Flexbox

Primero qué es un estilo y cómo se escribe con StyleSheet; después cómo se colocan las cosas con flexbox.

Qué es un estilo en React Native

No hay CSS ni ficheros de estilos. Un estilo es un objeto de JavaScript con propiedades en camelCase, que se pasa a la prop style de un componente.

1 · En línea

<View style={{ padding: 8 }} />
Las dos llaves: una de JSX y otra del objeto. Cómodo para algo puntual; con muchos estilos se llena el JSX.

2 · Con StyleSheet.create

style={estilos.caja}
Los estilos se definen aparte, con nombre, y el JSX queda limpio. Es lo recomendado.

3 · Combinados (array)

style={[estilos.base, activo && estilos.activo]}
Varios estilos a la vez; el último gana. Para versiones y condiciones.

Reglas que cambian respecto al CSS

En CSSEn React NativeNota
background-color: redbackgroundColor: 'red'camelCase, un valor con comillas
padding: 16pxpadding: 16Número sin “px” (píxeles lógicos)
width: 50%width: '50%'Porcentajes, entre comillas
font-weight: boldfontWeight: 'bold'Valores de texto entre comillas
border: 1px solid #cccborderWidth: 1, borderColor: '#ccc'No hay atajos tipo border ni background; se escribe cada propiedad
.clase { … }, selectores, :hover—No existen. Cada componente recibe su style
Herencia (texto hereda color del padre)Solo entre Text anidadosUn View no pasa su color a los Text

Probar estilos en vivo

Mueve los controles y mira cómo cambia la tarjeta y el código StyleSheet que lo produce.

Una tarjeta con StyleSheet.create, paso a paso

import { StyleSheet, Text, View } from 'react-native';

export default function Tarjeta({ nombre }) {
  return (
    <View style={estilos.caja}>
      <Text style={estilos.titulo}>{nombre}</Text>
      <Text style={estilos.detalle}>Pulsa para ver más</Text>
    </View>
  );
}

const estilos = StyleSheet.create({
  caja: {
    backgroundColor: '#ffffff',
    padding: 16,
    borderRadius: 12,
    borderWidth: 1,
    borderColor: '#dddddd',
    marginBottom: 12,
  },
  titulo: { fontSize: 20, fontWeight: 'bold', color: '#234c3b' },
  detalle: { fontSize: 14, color: '#666666' },
});

¿Por qué StyleSheet.create y no un objeto normal?

  • Orden: todos los estilos del fichero en un solo sitio, con nombre.
  • Avisos: si escribes mal una propiedad (backgroudColor), lo detecta.
  • Reutilización: el mismo estilo se usa en varios elementos.
  • Funciona exactamente igual con un objeto normal (const caja = {…}), pero StyleSheet.create es la convención.

Combinar estilos: versiones y condiciones

function Boton({ texto, activo, peligro }) {
  return (
    <Pressable style={[estilos.base, activo && estilos.activo, peligro && estilos.peligro]}>
      <Text style={estilos.texto}>{texto}</Text>
    </Pressable>
  );
}

const estilos = StyleSheet.create({
  base:    { padding: 12, borderRadius: 8, backgroundColor: '#cccccc' },
  activo:  { backgroundColor: '#234c3b' },
  peligro: { backgroundColor: '#b3541a' },
  texto:   { color: '#ffffff', textAlign: 'center' },
});

Errores típicos con estilos: (1) poner color o fontSize en un View (solo valen en Text); (2) escribir '16px' en vez de 16; (3) usar background-color en vez de backgroundColor; (4) esperar que un Text herede el color de su View; (5) olvidar borderColor al poner borderWidth (sale negro); (6) poner un estilo después en el array y que “pise” otro sin querer.

Flexbox: colocar las cosas

La clave: un contenedor tiene un eje principal (flexDirection) y un eje contrario.
  • justifyContent reparte los hijos a lo largo del eje principal.
  • alignItems los coloca en el eje contrario.
  • Por defecto el eje principal es vertical (column), al revés que en CSS.
<View style={{
  flex: 1,
  flexDirection: 'row',        // fila (por defecto: 'column')
  justifyContent: 'center',    // eje PRINCIPAL
  alignItems: 'center',        // eje CONTRARIO
  gap: 8,
}}>
  <Caja>A</Caja>
  <Caja>B</Caja>
  <Caja>C</Caja>
</View>
PropiedadPara qué
flex: 1Ocupa todo el espacio libre. Si hay hermanos con flex: 2, reparten proporcionalmente.
width, heightTamaño fijo (números = píxeles lógicos) o porcentaje '50%'.
padding, marginEspacio interior / exterior. También paddingHorizontal, marginTop…
backgroundColor, colorColor de fondo / de texto (color solo en Text).
borderWidth, borderColor, borderRadiusBorde y esquinas redondeadas.
position: 'absolute'Saca el elemento del flujo; se coloca con top/left/right/bottom.
fontSize, fontWeight, textAlignTexto.
StyleSheet.create({})Agrupa estilos con nombre y los valida.
style={[a, b]}Combina estilos; el último gana. Útil para condicionales: [estilos.base, activo && estilos.activo].

7 · Estado y eventos

El estado es la memoria del componente. Cambiarlo con setX es lo que hace que la pantalla se actualice.

function Contador() {
  const [n, setN] = useState(0);
  const [texto, setTexto] = useState('');

  return (
    <View>
      <Text>Pulsado {n} veces</Text>
      <Pressable onPress={() => setN(n + 1)}><Text>+1</Text></Pressable>
      <TextInput value={texto} onChangeText={setTexto} />
      <Text>Escribiste: {texto}</Text>
    </View>
  );
}

✅ Haz

  • setLista([...lista, nuevo]) (copia nueva)
  • Pasar la función: onPress={guardar}
  • Un useState por cada dato independiente

❌ No hagas

  • lista.push(nuevo) (modifica el original)
  • contador = contador + 1 (no repinta)
  • onPress={guardar()} (se ejecuta al pintar)

8 · Efectos: cosas que pasan al aparecer, cambiar o desaparecer

useEffect es para hablar con el “mundo exterior”: red, temporizadores, suscripciones, sensores.

function Reloj() {
  const [seg, setSeg] = useState(0);

  useEffect(() => {
    const id = setInterval(() => setSeg(s => s + 1), 1000);
    return () => clearInterval(id);     // limpieza
  }, []);

  return <Text>{seg} segundos</Text>;
}
EscriboSe ejecuta
useEffect(fn, [])Una vez, al aparecer la pantalla.
useEffect(fn, [x])Al aparecer y cada vez que x cambia.

9 · Listas, keys y renderizado condicional

Casi toda app es “una lista de cosas”. Aquí ves cómo se filtra, se pinta y se gestiona que esté vacía.

const [items, setItems] = useState(['Pan', 'Leche']);

  data={visibles}
  keyExtractor={i => i}
  renderItem={({ item }) => <Text>{item}</Text>}
  ListEmptyComponent={<Text>No hay resultados</Text>}
/>
¿Por qué key? Cuando la lista cambia, React compara la anterior y la nueva. Con una key única por elemento sabe qué fila se ha añadido, movido o quitado y solo toca esa. Usa el id de tus datos; no uses el índice si la lista puede reordenarse.

// src/app/lugar/[id].jsx
import { Stack, useLocalSearchParams } from "expo-router";
import { Text, View } from "react-native";
import { lugares } from "../../data/lugares";

export default function Lugar() {
    const { id } = useLocalSearchParams();
    const lugar = lugares.find(l => l.id === id);

    if (!lugar) return <Text>Lugar no encontrado</Text>;

    return (
        <View>
            <Stack.Screen options={{ title: lugar.nombre }} />
            <Text>{lugar.nombre}</Text>
            <Text>{lugar.descripcion}</Text>
        </View>
    );
}

Por qué se pasa solo el id y no todo el lugar

Las rutas llevan texto simple. Pasar el nombre, la descripción y el color por la ruta sería largo y se desincroniza si cambias un dato. Con solo el id, la pantalla de detalle busca el lugar en los datos y siempre muestra la información actual. Es el mismo patrón que lista → detalle de la práctica.
Errores típicos en este montaje: (1) el fichero debe llamarse [id].jsx con corchetes, dentro de una carpeta (lugar/); (2) el id de los datos y el de la ruta tienen que coincidir exactamente (mayúsculas incluidas) y ser texto; (3) contar mal los ../ en los imports: index.jsx usa ../data/lugares y lugar/[id].jsx usa ../../data/lugares (usa la calculadora de la sección 2); (4) olvidar la key en el map; (5) borra el local1.jsx vacío de src/app: esta pantalla dinámica lo sustituye y un fichero vacío en esa carpeta da error; (6) escribir el pathname con el valor ya puesto ("/lugar/gotham") y a la vez params: o una cosa o la otra; con "/lugar/[id]" el id va en params.

Flujos de navegación: del login al dashboard

Un Stack sirve igual para flujos paso a paso (bienvenida → login → dashboard). Lo que cambia es cómo navegas: depende de si el usuario debe poder volver o no.

// src/app/login.jsx
import { router } from 'expo-router';

export default function Login() {
  function entrar() {

  return (
    <View>

Impedir saltarse el login (rutas protegidas)

Hasta aquí, nada evita que alguien abra /dashboard directamente. Con Stack.Protected las pantallas del dashboard solo existen si hay sesión.

// src/app/_layout.jsx
import { Stack } from 'expo-router';
import { useState } from 'react';

export default function Layout() {
  const [logueado, setLogueado] = useState(false);   // en una app real viene de una sesión compartida

  return (
    <Stack>
      <Stack.Protected guard={!logueado}>
        <Stack.Screen name="login" />
      </Stack.Protected>
      <Stack.Protected guard={logueado}>
        <Stack.Screen name="dashboard" />
        <Stack.Screen name="perfil" />
      </Stack.Protected>
    </Stack>
  );
}
Esto es un esquema, no un login completo. Para que login.jsx pueda cambiar logueado hace falta compartir el estado entre ficheros (un contexto de React) y guardar la sesión (AsyncStorage). Además, la sintaxis de rutas protegidas depende de la versión: revisa la documentación de Expo Router de tu SDK. Para la práctica MyPlaces no lo necesitas.

11 · Anatomía de una pantalla típica

Casi todas tus pantallas siguen este orden. Memorízalo y sabrás dónde va cada cosa.

// 1. IMPORTS
import { useEffect, useState } from 'react';
import { ActivityIndicator, FlatList, StyleSheet, Text, View } from 'react-native';

export default function Pantalla() {
  // 2. ESTADO
  const [datos, setDatos] = useState([]);
  const [cargando, setCargando] = useState(true);

  // 3. EFECTOS (cosas que pasan al aparecer)
  useEffect(() => {
    fetch(URL).then(r => r.json()).then(d => { setDatos(d); setCargando(false); });
  }, []);

  // 4. CÁLCULOS Y EVENTOS
  const total = datos.length;

  // 5. RENDER (lo que se ve)
  if (cargando) return <ActivityIndicator />;
  return (
    <View style={estilos.contenedor}>
      <Text>{total} elementos</Text>
      <FlatList data={datos} renderItem={({ item }) => <Text>{item.title}</Text>} />
    </View>
  );
}

// 6. ESTILOS
const estilos = StyleSheet.create({ contenedor: { flex: 1, padding: 16 } });
