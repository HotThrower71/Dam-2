JSX en 1 minuto

Lo que ves dentro del return (<View>…</View>) se llama JSX: es JavaScript con etiquetas. Reglas que debes saber:

ReglaEjemploQué significa
Llaves = JavaScript<Text>{nombre}</Text>Dentro de { } puedes poner variables, operaciones o llamadas a funciones.
Un solo elemento raíz<View>…</View>Un componente devuelve UNA caja. Si necesitas varias, envuélvelas en <View> o en <>…</> (fragmento, no pinta nada).
Props = atributos<TarjetaLugar lugar={item} />Así pasas datos a un componente. Dentro los recibes como parámetro: function TarjetaLugar({ lugar }).
Mostrar si se cumple{error !== '' && <Text>{error}</Text>}Si la condición es falsa, no se pinta nada. Es un “if” dentro del JSX.
Uno u otro{cargando ? <Spinner/> : <Lista/>}Operador ternario: condición ? siSi : siNo.
EventosonPress={guardar}Pasas la función (sin paréntesis). Con paréntesis la ejecutarías al pintar la pantalla.
Error típico: onPress={guardar()} ejecuta la función al instante. Lo correcto es onPress={guardar} o onPress={() => guardar(5)} si necesitas pasar argumentos.

Estilos con StyleSheet

No hay CSS. Los estilos son objetos de JavaScript con nombres en camelCase (backgroundColor, no background-color). Se aplican con la prop style.

import { StyleSheet, Text, View } from 'react-native';

export default function Ejemplo() {
  return (
    <View style={estilos.caja}>
      <Text style={estilos.titulo}>Hola</Text>
    </View>
  );
}

// StyleSheet.create define los estilos una sola vez y los valida
const estilos = StyleSheet.create({
  caja:   { flex: 1, padding: 16, backgroundColor: '#fff' },
  titulo: { fontSize: 24, fontWeight: 'bold', color: '#234c3b' },
});
PropiedadQué hace
flex: 1La caja ocupa todo el espacio disponible de su padre.
flexDirection'column' (por defecto, de arriba abajo) o 'row' (en fila).
justifyContentAlinea los hijos en el eje principal: center, space-between…
alignItemsAlinea los hijos en el eje contrario: center, flex-start…
padding / marginEspacio interior / exterior (números, sin “px”).
gapSeparación entre hijos.
borderWidth, borderColor, borderRadiusBorde y esquinas redondeadas.
fontSize, fontWeight, colorSolo valen en Text.
Por defecto todo se apila en columna (al revés que en la web). Y los estilos de texto no se heredan de View a Text.

Hooks (funciones que empiezan por use)

HookIdea
useStateMemoria del componente. Si cambia, la pantalla se repinta. const [n, setN] = useState('')
useEffect“Haz esto cuando la pantalla aparezca” (cargar datos, pedir permisos…)
useLocalSearchParamsLee parámetros de la ruta (por ejemplo el id)

Cómo funcionan los hooks, uno a uno

useState

Devuelve una pareja [valor, funciónParaCambiarlo]. El argumento es el valor inicial.

const [contador, setContador] = useState(0);
setContador(contador + 1);   // la pantalla se repinta con el nuevo valor

Nunca modifiques el valor directamente (contador = 5): usa siempre el set…. Con listas, crea una nueva: setLista([...lista, nuevo]).

useEffect

Ejecuta código después de pintar la pantalla. El segundo argumento (array de dependencias) decide cuándo.

useEffect(() => {
  cargar();          // se ejecuta una vez al aparecer
}, []);              // [] = solo la primera vez

useEffect(() => {
  const sub = NetInfo.addEventListener(...);
  return () => sub();  // limpieza al salir de la pantalla
}, []);

Con [x] se vuelve a ejecutar cada vez que x cambia. Sin array, en cada repintado (casi nunca lo quieres).

useFocusEffect + useCallback

Como useEffect, pero se ejecuta cada vez que la pantalla vuelve a estar visible (p. ej. al volver del formulario). useCallback evita que la función se recree en cada pintado; es obligatorio envolver así lo que pasas a useFocusEffect.

useLocalSearchParams

Devuelve un objeto con los parámetros de la ruta actual. En detall/[id].jsx: const { id } = useLocalSearchParams();. Los valores llegan siempre como texto.

useRouter / router

Navegar desde código: router.push('/nuevo') abre una pantalla encima; router.back() vuelve; router.replace(...) sustituye la actual.

Estado = datos que cambian y que se ven. Si lo guardas en una variable normal, la pantalla no se actualiza.

Los dos primeros ficheros: _layout.jsx e index.jsx

Dentro de src/app/ cada fichero es una pantalla, y los dos primeros que tendrás son estos. Analogía: una tele.

📺 _layout.jsx = el marco

El aparato con su borde. No cambia nunca. Su trabajo es <Stack />: “aquí dentro se muestra la pantalla que toque, con su barra de arriba”. Se ejecuta una vez y se queda.

🎬 index.jsx = un canal

Lo que sale al encender: la primera pantalla (ruta /). Luego añadirás más canales (nuevo.jsx, descubre.jsx) y cambiarás entre ellos con el mismo marco.
┌───────────────────────────┐
│ index                     │  ← barra: la pone <Stack /> (_layout.jsx)
├───────────────────────────┤
│   MyPlaces                │  ← contenido: viene de index.jsx
│   Tour                    │
└───────────────────────────┘
El nombre del fichero ES la ruta: index.jsx = /, nuevo.jsx = /nuevo. Si lo llamas indice.jsx no habrá pantalla de inicio (“Unmatched Route”).
Regla corta: lo que cambia de una pantalla a otra va en la pantalla; lo que las rodea a todas (barra, navegación) va en el layout. Y en cada fichero puede haber muchas funciones, pero solo un export default: la pieza principal (en src/app/, la pantalla). Más detalle, con simulaciones, en React Native desde cero.

¿Qué es un Stack?

Stack = “pila”. Como folios apilados en una mesa: solo ves el de arriba. push pone uno encima (abre una pantalla); back quita el de arriba (vuelve). <Stack /> es el componente que gestiona esa pila, dibuja la de arriba y añade la barra superior con la flecha ‹.

push('/nuevo')       push('/detall/3')       back()
┌──────────┐         ┌──────────┐            ┌──────────┐
│          │         │ detall/3 │ ← ves      │          │
│ nuevo    │ ← ves   │ nuevo    │            │ nuevo    │ ← ves
│ index    │         │ index    │            │ index    │
└──────────┘         └──────────┘            └──────────┘
Las pantallas de debajo no se destruyen: por eso, al volver a la lista, hay que releer los datos con useFocusEffect (apartado C). Para tu práctica (lista → detalle → formulario → volver) Stack es lo adecuado; Slot no tiene pila ni barra, y Tabs pone pestañas. Simulación interactiva en React Native desde cero.

1 · Preparar el proyecto

Partimos de una carpeta vacía. Todo el proyecto se crea con comandos, en este orden.

Requisitos previos

  • Node.js (versión LTS) y npm: comprueba con node -v y npm -v.
  • Móvil con la app Expo Go (misma wifi que el PC) o un emulador de Android/iOS.
Montamos el proyecto a mano, sin plantilla: así solo existe lo que tú pones y no hay que limpiar nada ni pelearse con TypeScript.

// src/app/_layout.jsx
import { Stack } from 'expo-router';

export default function Layout() {
  return <Stack />;
}

// src/app/index.jsx
import { Text, View } from 'react-native';

export default function Inicio() {
  return (
    <View>
      <Text>MyPlaces</Text>
    </View>
  );
}

¿Qué hace cada línea?

  • _layout.jsx es el marco de toda la app. Expo Router lo carga primero y dentro pinta la pantalla que toque.
  • <Stack /> (de expo-router) crea una navegación “pila”: cada pantalla nueva se apila encima y la barra superior tiene el botón atrás automático.
  • export default function: Expo Router busca el export por defecto de cada fichero; ese componente es la pantalla.
  • index.jsx es la ruta / (la pantalla de inicio). nuevo.jsx sería /nuevo; detall/[id].jsx sería /detall/3.
  • <View> y <Text> vienen de react-native. Todo texto va dentro de <Text> o la app falla.

// src/app/detall/[id].jsx
import { useLocalSearchParams } from 'expo-router';
import { Text, View } from 'react-native';
import { llocs } from '../../data/llocs';

export default function Detalle() {
  const { id } = useLocalSearchParams();            // "1", "2"… (texto)
  const lugar = llocs.find((l) => l.id === id);     // busca el primero que cumpla

  if (!lugar) return <Text>Lugar no encontrado</Text>;
  return (
    <View style={{ padding: 16 }}>
      <Text style={{ fontSize: 24 }}>{lugar.nombre}</Text>
      <Text>{lugar.descripcion}</Text>
    </View>
  );
}

B · Formulario y validación

Pantalla para añadir lugar (nombre + descripción). No deja guardar con el nombre vacío, enseña el error y permite volver.

  • TextInput + useState para cada campo (onChangeText).
  • Estado extra error: si nombre.trim() === '' → mostrar mensaje y no guardar.
  • router.back() para volver a la lista.
const [nombre, setNombre] = useState('');
const [descripcion, setDescripcion] = useState('');
const [error, setError] = useState('');

function guardar() {
  if (nombre.trim() === '') {
    setError('El nombre no puede estar vacío');
    return;                       // se corta aquí: no se guarda
  }
  setError('');
  // ...guardar con AsyncStorage (apartado C)...
  router.back();
}

<TextInput value={nombre} onChangeText={setNombre} placeholder="Nombre" />
{error !== '' && <Text style={{ color: 'red' }}>{error}</Text>}
¿Quieres la guía completa de formularios (varios campos, validación por campo, teclado en móvil, componente Campo, simulación)? Está en React Native desde cero · Formularios.

Qué hace cada pieza

PiezaQué hace
value + onChangeTextEs un campo “controlado”: lo que se ve viene siempre del estado (value={nombre}) y cada tecla actualiza el estado (onChangeText={setNombre}). Así siempre sabes qué ha escrito el usuario.
placeholderTexto gris de ayuda cuando el campo está vacío.
multilinePermite varias líneas (útil para la descripción).
.trim()Quita espacios al principio y final. Sin él, un nombre de solo espacios pasaría la validación.
return; tempranoSale de la función en ese punto. Es la forma más sencilla de “si falla, no sigas”.
router.back()Cierra la pantalla actual y vuelve a la anterior.

Pantalla completa

// src/app/nuevo.jsx
import { router } from 'expo-router';
import { useState } from 'react';
import { Pressable, Text, TextInput, View } from 'react-native';
import { leerLugares, guardarLugares } from '../storage/lugares';

export default function Nuevo() {
  const [nombre, setNombre] = useState('');
  const [descripcion, setDescripcion] = useState('');
  const [error, setError] = useState('');

  async function guardar() {
    if (nombre.trim() === '') {
      setError('El nombre no puede estar vacío');
      return;
    }
    const lista = await leerLugares();
    const nuevo = { id: Date.now().toString(), nombre: nombre.trim(), descripcion };
    await guardarLugares([...lista, nuevo]);   // copia de la lista + el nuevo
    router.back();
  }

  return (
    <View style={{ padding: 16, gap: 8 }}>
      <TextInput value={nombre} onChangeText={setNombre} placeholder="Nombre" style={{ borderWidth: 1, padding: 8 }} />
      <TextInput value={descripcion} onChangeText={setDescripcion} placeholder="Descripción" multiline style={{ borderWidth: 1, padding: 8 }} />
      {error !== '' && <Text style={{ color: 'red' }}>{error}</Text>}
      <Pressable onPress={guardar}><Text>Guardar</Text></Pressable>
      <Pressable onPress={() => router.back()}><Text>Cancelar</Text></Pressable>
    </View>
  );
}
[...lista, nuevo] es el operador spread: crea un array nuevo con todos los elementos de lista y añade nuevo al final. En React siempre se crean copias en vez de modificar el original.

C · Persistencia local AsyncStorage

Guardar los lugares para que sigan ahí al cerrar y abrir la app.

AsyncStorage es un “almacén de clave → texto”. Solo guarda strings, así que conviertes con JSON.stringify (guardar) y JSON.parse (leer). Todas sus funciones son asíncronas: usa await.
// src/storage/lugares.js
import AsyncStorage from '@react-native-async-storage/async-storage';
const CLAVE = 'lugares';

export async function leerLugares() {
  const texto = await AsyncStorage.getItem(CLAVE);
  return texto ? JSON.parse(texto) : [];          // lista vacía si no hay nada
}
export async function guardarLugares(lista) {
  await AsyncStorage.setItem(CLAVE, JSON.stringify(lista));
}
export async function eliminarLugar(id) {
  const lista = await leerLugares();
  await guardarLugares(lista.filter(l => l.id !== id));
}

Estas funciones hay que crearlas tú. leerLugares y guardarLugares se definen en el fichero src/storage/lugares.js (el código de arriba) y se importan desde el formulario y la lista. Si no creas ese fichero, el import falla. Los nombres son orientativos: en el proyecto MyPlaces se usan readPlaces y savePlaces en src/storage/placesStorage.js. Lo importante es que el nombre del import coincida con el del export. Mapa completo de qué se define y dónde en React Native desde cero · sección 2.

Lista con borrado (index.jsx final)

// src/app/index.jsx
import { Link, useFocusEffect } from 'expo-router';
import { useCallback, useState } from 'react';
import { FlatList, Pressable, Text, View } from 'react-native';
import { eliminarLugar, leerLugares } from '../storage/lugares';
import TarjetaLugar from '../components/TarjetaLugar';

export default function Lista() {
  const [lugares, setLugares] = useState([]);

  useFocusEffect(useCallback(() => {
    leerLugares().then(setLugares);       // al mostrarse: leer del disco
  }, []));

  async function borrar(id) {
    await eliminarLugar(id);              // 1. borrar del almacenamiento
    setLugares(await leerLugares());      // 2. releer para repintar
  }

  return (
    <View style={{ flex: 1, padding: 16 }}>
      <Link href="/nuevo" asChild><Pressable><Text>+ Añadir lugar</Text></Pressable></Link>
      <FlatList
        data={lugares}
        keyExtractor={(l) => l.id}
        renderItem={({ item }) => <TarjetaLugar lugar={item} onBorrar={() => borrar(item.id)} />}
        ListEmptyComponent={<Text>Aún no hay lugares. ¡Añade el primero!</Text>}
      />
    </View>
  );
}
leerLugares().then(setLugares) es lo mismo que const l = await leerLugares(); setLugares(l); pero sin async. Se usa dentro de useFocusEffect porque su función no puede ser async.

En TarjetaLugar añade un botón que llame a la prop onBorrar: <Pressable onPress={onBorrar}><Text>Eliminar</Text></Pressable>. Así el componente sigue siendo reutilizable: no sabe cómo se borra, solo avisa al padre.

Para el id nuevo vale Date.now().toString().

D · Consulta HTTP: pantalla «Descobreix»

Pedir datos a una API pública con fetch y mostrar tres estados: cargando, error, vacío.

⏳ cargando→✅ datosó❌ erroró📭 vacío
  • APIs sin clave que sirven: https://jsonplaceholder.typicode.com/posts, Open-Meteo, REST Countries, Nominatim (OpenStreetMap)…
  • Apunta en el README cuál usas (lo piden).
const [datos, setDatos] = useState([]);
const [cargando, setCargando] = useState(true);
const [error, setError] = useState('');

async function cargar() {
  setCargando(true); setError('');
  try {
    const res = await fetch('https://jsonplaceholder.typicode.com/posts?_limit=10');
    if (!res.ok) throw new Error('Respuesta ' + res.status);
    setDatos(await res.json());
  } catch (e) {
    setError('No se pudo cargar. Revisa tu conexión.');
  } finally {
    setCargando(false);
  }
}
useEffect(() => { cargar(); }, []);

if (cargando) return <ActivityIndicator />;
if (error)    return <><Text>{error}</Text><Button title="Reintentar" onPress={cargar} /></>;
if (datos.length === 0) return <Text>No hay resultados</Text>;
// si no: <FlatList data={datos} ... />
En MyPlaces se usa la API Open-Meteo Geocoding (https://geocoding-api.open-meteo.com/v1/search), que busca lugares por nombre y no necesita clave. Dos detalles que conviene saber: pide al menos 2 letras en name, y cuando no hay resultados no envía el campo results (por eso se usa datos.results ?? []). Implementación completa en src/app/descubre.jsx, con cuatro estados (inicial, cargando, error y ok) en una sola variable estado en vez de tres booleanos.

Qué hace cada pieza

PiezaQué hace
fetch(url)Hace la petición HTTP (GET por defecto). Devuelve una promesa con la respuesta (cabeceras y estado, aún no los datos).
res.oktrue si el código HTTP es 200–299. fetch NO falla con 404 o 500, hay que mirarlo tú.
res.json()Lee el cuerpo y lo convierte de JSON a objeto/array. También es asíncrona: usa await.
throw new Error(...)Lanza un error a propósito; salta directamente al catch.
try { } catch (e) { }Ejecuta el bloque; si algo falla (sin internet, JSON mal, throw), pasa al catch en vez de romper la app.
finally { }Se ejecuta SIEMPRE, haya error o no. Ideal para apagar el “cargando”.
ActivityIndicatorLa rueda de carga nativa.
ButtonBotón nativo sencillo: title y onPress. Para botones con diseño propio usa Pressable.
useEffect(..., [])Lanza la carga una vez al abrir la pantalla.

Por qué tres estados

La pantalla siempre está en una de estas situaciones y tienes que pintar algo para cada una. Si no, el usuario ve una pantalla en blanco sin saber qué pasa. Los if … return del ejemplo se evalúan en orden: primero cargando, después error, después vacío, y si nada de eso, la lista.

Pantalla completa «Descobreix»

// src/app/descubre.jsx
import { useEffect, useState } from 'react';
import { ActivityIndicator, Button, FlatList, Text, View } from 'react-native';

export default function Descubre() {
  const [datos, setDatos] = useState([]);
  const [cargando, setCargando] = useState(true);
  const [error, setError] = useState('');

  async function cargar() {
    setCargando(true);
    setError('');
    try {
      const res = await fetch('https://jsonplaceholder.typicode.com/posts?_limit=10');
      if (!res.ok) throw new Error('Respuesta ' + res.status);
      setDatos(await res.json());
    } catch (e) {
      setError('No se pudo cargar. Revisa tu conexión.');
    } finally {
      setCargando(false);
    }
  }

  useEffect(() => { cargar(); }, []);

  if (cargando) return <ActivityIndicator size="large" />;
  if (error) return (
    <View><Text>{error}</Text><Button title="Reintentar" onPress={cargar} /></View>
  );
  if (datos.length === 0) return <Text>No hay resultados</Text>;

  return (
    <FlatList
      data={datos}
      keyExtractor={(d) => String(d.id)}
      renderItem={({ item }) => <Text style={{ padding: 8 }}>{item.title}</Text>}
    />
  );
}
Recuerda registrar la pantalla en el menú: añade un <Link href="/descubre"> en index.jsx y, si quieres título, <Stack.Screen name="descubre" options={{ title: 'Descobreix' }} /> en _layout.jsx.
try/catch recoge errores de red; res.ok recoge errores HTTP (404, 500), que fetch no lanza solo.

E · Ubicación y permisos expo-location

Botón «Utilitza la meva ubicació»: pide permiso, muestra coordenadas, y si se deniega la app sigue funcionando.

Pulsar botón→Pedir permiso→¿Concedido?→✅ coordenadas / ❌ mensaje
import * as Location from 'expo-location';

const [coords, setCoords] = useState(null);
const [mensaje, setMensaje] = useState('');

async function usarUbicacion() {
  const { status } = await Location.requestForegroundPermissionsAsync();
  if (status !== 'granted') {
    setMensaje('Permiso denegado. Puedes seguir usando la app sin ubicación.');
    return;
  }
  const pos = await Location.getCurrentPositionAsync({});
  setCoords(pos.coords);        // pos.coords.latitude / .longitude
}

<Pressable onPress={usarUbicacion}><Text>Utilitza la meva ubicació</Text></Pressable>
{coords && <Text>{coords.latitude}, {coords.longitude}</Text>}
{mensaje !== '' && <Text>{mensaje}</Text>}
En MyPlaces está en src/app/ubicacion.jsx (botón «Mi ubicación» del menú). Diferencias con el ejemplo de arriba: usa un solo estado estado (inicial, cargando, ok, denegado o error); intenta sacar una dirección con reverseGeocodeAsync (si falla, solo enseña las coordenadas); si se deniega el permiso ofrece «Abrir ajustes» con Linking.openSettings() (solo en el móvil); y app.json lleva el plugin expo-location con el texto del permiso. Tras tocar app.json hay que reiniciar Expo.

Qué hace cada pieza

PiezaQué hace
import * as LocationImporta todas las funciones del módulo bajo el nombre Location.
requestForegroundPermissionsAsync()Muestra el diálogo del sistema “¿Permitir ubicación?”. Devuelve un objeto con status: 'granted', 'denied' o 'undetermined'. Si ya decidió antes, no vuelve a preguntar y devuelve la decisión guardada.
getCurrentPositionAsync(opciones)Pide el GPS y devuelve un objeto con coords (latitude, longitude, accuracy…) y timestamp. Puede tardar unos segundos.
{ accuracy: Location.Accuracy.Balanced }Opción para elegir precisión (más precisión = más batería).
const { status } = ...“Desestructurar”: saca solo status del objeto devuelto.

Por qué hay que pedir permiso

Android e iOS no dejan acceder a la ubicación sin que el usuario lo acepte. Si dice que no, la app no debe romperse: se muestra un mensaje y todo lo demás sigue funcionando. Por eso el return temprano cuando status !== 'granted'.

Con control de errores

async function usarUbicacion() {

    setMensaje('');
  } catch (e) {

En el emulador de Android fija una posición falsa en Extended controls → Location. En iOS: Features → Location.
Foreground = solo con la app abierta. Es lo único que necesitas.

F · Conectividad NetInfo

Mostrar si hay conexión y el tipo de red; no lanzar consultas si no hay.

import NetInfo from '@react-native-community/netinfo';

const [red, setRed] = useState({ conectado: true, tipo: '' });

useEffect(() => {
  const dejarDeEscuchar = NetInfo.addEventListener(estado => {
    setRed({ conectado: estado.isConnected, tipo: estado.type }); // wifi, cellular, none...
  });
  return dejarDeEscuchar;      // limpieza al salir de la pantalla
}, []);

// antes de pedir datos:
if (!red.conectado) { setError('Sin conexión'); return; }

{!red.conectado && <Text>📴 Sin conexión</Text>}
<Text>Red: {red.tipo}</Text>
En MyPlaces está dividido en dos piezas reutilizables: el hook src/hooks/useRed.js (escucha NetInfo y devuelve { conectado, tipo }) y el componente src/components/BannerRed.jsx (la barra). La barra va en _layout.jsx para verse en todas las pantallas, y «Descubre» usa el mismo hook para no lanzar la consulta cuando no hay conexión. Detalle: isConnected e isInternetReachable pueden ser null al principio, por eso solo se considera «sin conexión» cuando valen false. Más sobre hooks propios y estado compartido en React Native desde cero.

Qué hace cada pieza

PiezaQué hace
NetInfo.addEventListener(fn)Registra una función que se ejecuta cada vez que cambia la conexión (y una vez al empezar). Devuelve otra función para darse de baja.
estado.isConnectedtrue/false, o null mientras no lo sabe.
estado.isInternetReachableSi realmente hay internet (puedes estar en una wifi sin salida).
estado.typeTipo de red: wifi, cellular, none, unknown…
return dejarDeEscucharDentro de useEffect, la función que devuelves es la limpieza: React la llama al cerrar la pantalla. Sin ella el listener se quedaría funcionando para siempre.
NetInfo.fetch()Consulta puntual (una sola vez) en vez de escuchar cambios.

Componente BannerRed completo

// src/components/BannerRed.jsx
import NetInfo from '@react-native-community/netinfo';
import { useEffect, useState } from 'react';
import { Text, View } from 'react-native';

export default function BannerRed() {
  const [red, setRed] = useState({ conectado: true, tipo: '' });

  useEffect(() => {
    const dejarDeEscuchar = NetInfo.addEventListener((estado) => {
      setRed({ conectado: estado.isConnected !== false, tipo: estado.type });
    });
    return dejarDeEscuchar;
  }, []);

  return (
    <View style={{ padding: 6, backgroundColor: red.conectado ? '#d8f0e0' : '#f6d5d5' }}>
      <Text>{red.conectado ? 'Red: ' + red.tipo : '📴 Sin conexión'}</Text>
    </View>
  );
}

Para evitar consultas sin red en «Descobreix», pásale la información como prop o consulta antes de cargar: const e = await NetInfo.fetch(); if (!e.isConnected) { setError('Sin conexión'); setCargando(false); return; }

Haz un componente BannerRed y úsalo en varias pantallas: cuenta como “componente reutilizable” extra.
isConnected puede ser null al principio; el código de arriba lo trata como “no conectado”. Si quieres evitarlo: estado.isConnected !== false.

Errores frecuentes

  • “Text strings must be rendered within a <Text>”: has puesto texto suelto dentro de un View.
  • La pantalla no se actualiza: cambiaste una variable normal en vez de usar setX de useState.
  • Al volver no aparece el dato nuevo: cargaste con useEffect([]) en vez de useFocusEffect.
  • onPress={f()} se ejecuta solo: debe ser onPress={f}.
  • Falta keyExtractor / key en listas: aviso de React y comportamientos raros.
  • Módulo nativo no encontrado: lo instalaste con npm install; usa npx expo install y reinicia con npx expo start -c.
  • El móvil no conecta: PC y móvil deben estar en la misma wifi, o prueba npx expo start --tunnel.
